# M100M-B2 实机测试记录（2026-09-23）

## 结论

本次确认：该实机可用单个 MQTT publication 发送 **2233 字节**的完整反射率记录，无应用层分片；60 秒负载中 **300/300 条在地面完整验证，300/300 条地面 DTA1 ACK 经蜂窝网络返回 COM8 并清池**。接收平均速率约 **5.0015 Hz**。

这不是严格无抖动的 200 ms 周期保证。60 秒测试最大提交滞后 378 ms，超过一个周期，所以原始 `summary.json` 的 `passed` 为 **false**，`error` 为 null。保留这个结果，不以完整送达替代严格时序资格。尚未验证长时间任务、弱网、GPS/事件混合负载或 ESP32 生产集成。

## 环境与边界

- USB-to-TTL 接 RX/TX，端口 COM8；未操作 ESP32 或 COM9。
- `ATI` 实机响应：`AirM2M_780EPM_V2007_LTE_AT`。这是原生 AT 固件，不能直接套用透传 DTU 的私有配置命令。
- 出厂 UART 实测 115200，测试改为 460800；关闭回显，未执行 `AT&W`、刷机或恢复出厂。
- 原生 `AT+MPUBEX` 显式长度二进制发送；上行 QoS 1，地面 DTA1 下行 QoS 0，均不 retain。
- 每条记录为有效 DHR1：711 个波长点、头部及 CRC，共 2233 字节。地面复用既有解码器和 DTA1 编码器，并逐字节比对预期数据。
- 独立随机测试 topics/client IDs；接收端订阅 SUBACK 就绪后才启动负载。测试协议不替换生产遥测线格式。
- 512 项应用池，3 秒 ACK 超时、最多一次重试，10 秒最大寿命。
- 固件、现有 mission viewer 和 ground_app 未因本测试修改。

## 原生 AT 流控发现

首次短测成功收到一个 2233 字节包，但在前条 QoS-1 PUBACK 到达前继续 MPUBEX，模组返回 `+CME ERROR:767`。这不是大包无法发送。

修正 scratch 的模组提交流控后，同一时刻仅保留一个等待 PUBACK 的 AT 发布。**PUBACK 只允许下一次模组提交，不释放应用池；只有匹配身份、序号与 CRC 的地面 DTA1 才释放条目。** 接纳负载与串口 ACK 接收继续运行，不用固定间隔等待地面确认。

## 结果

| 指标 | 10 秒 smoke-02 | 60 秒 qualification-60s |
| --- | ---: | ---: |
| 预期 / 完整收到 / UART 确认 | 50 / 50 / 50 | 300 / 300 / 300 |
| 单条 MQTT payload | 2233 字节 | 2233 字节 |
| 应用池峰值 | 2 | 3 |
| 未首发峰值 / 等待地面 ACK 峰值 | 1 / 1 | 2 / 1 |
| 重试 / 过期 / 池溢出 | 0 / 0 / 0 | 0 / 0 / 0 |
| ACK RTT 均值 / P95 / 最大 | 226 / 266 / 281 ms | 230 / 266 / 610 ms |
| 本地 AT 提交均值 / 最大 | 52.5 / 63 ms | 54.6 / 63 ms |
| 首次提交滞后 P95 / 最大 | 44 / 50 ms | 215 / 378 ms |
| 接收平均速率 | 4.9934 Hz | 5.0015 Hz |
| 最大相邻接收间隔 | 250 ms | 562 ms |
| 原始严格资格结果 | passed=true | passed=false（周期滞后） |

接收平均速率用 `(记录数 - 1) / (最后接收时刻 - 首次接收时刻)` 计算；60 秒接收跨度 59.782 秒。首次提交至最后地面 ACK 返回约 60.000 秒。无残留池条目、无错误身份 ACK。

## 证据与复测

本机原始证据位于被 Git 忽略的 `results/smoke-01/`、`results/smoke-02/`、`results/qualification-60s/`，每组含 `summary.json` 与 `events.jsonl`。首次失败证据保留；后两次使用已修正的模组流控。计数器未出现的键代表未发生，不是漏报次数。

运行方法见 [README.md](README.md)。本机 `config.local.json` 的 `initial_baud` 已设为 **460800**；配置和日志不提交。成功测试结束已关闭 MQTT 会话并释放 COM8。重新上电后需确认当前波特率，不能假定本次设置一定持久化或一定恢复出厂值。

下一步建议在相同单包/DTA1 条件下做 10 分钟压力测试，再加入生产 GPS 批量包和事件负载；当前结果支持继续评估该模组，但不能直接宣布生产 5 Hz 链路已通过完整资格测试。
