# 光谱接收链路健康与轮询时序（2026-09-27）

本次保持 4 Hz 遥测、SPI 轮询、A-B 数据包布局不变。不涉及 GPIO21、电池控制或 IRQ 改造。

## 编译约束

SC16 服务每轮 `vTaskDelay(1)`，驱动通过 `sc16_polling_contract.h` 强制
`CONFIG_FREERTOS_HZ=1000`。100/500 Hz 等配置明确编译失败。默认配置本来就是 1000。
115200 baud、8N1 下空的 64 字节 FIFO 约 5.56 ms 填满；名义 1 ms 轮询留下约 4.56 ms，
还须扣除 SPI 和调度开销。这不是实时保证。原有硬件 FIFO 读函数的 64 字节截断保留。

## 统计边界与故障处理

采集生命周期任务在启动流前建立计数基线，天空预采集和双通道运行期间每约 100 ms
读取驱动原子计数，不访问 SPI 或 SD。所有停止路径在 `stop_acquisition_tasks()`
入口做最终快照并冻结，包含部分启动失败及异常清理。重复清理不能重复累计。
边界是任务进入 teardown，不是 A 命令到达的精确时刻；此后损失只属于关闭流诊断。

`acquisition_status_t.rx_overruns[2]` 和 `rx_software_drops[2]` 是当前段计数。
记录模块另外累计整个任务的统计，后续 START 不清除。累计损失非零时心跳 error 5，
已有更高优先级错误则保留原错误。不锁死 recorder、不阻止重启采集、不改变安全断电条件。

## SD 与地面事件

`MISSION.JSON` 增加可选字段，数组按 `[地面 A, 天空 B]` 排列：

```json
"acquisition_rx_loss": {
  "hardware_overruns": [0, 0],
  "software_dropped_bytes": [0, 0]
}
```

统计随原有 checkpoint、周期 flush、最终关闭写入，不额外同步写 SD。
软件字段为拒收字节数，硬件字段为 OE 标志观测次数，不能推断丢字节数。
旧文件缺少此字段表示没有此项统计，不表示零损失。

新增事件码 15 `acquisition_rx_loss`（error 级），使用原有 SD/MQTT 事件路径：

- `argument0`：0 地面 A，1 天空 B。
- `argument1`：bit0 硬件溢出，bit1 软件缓冲拒收；仅描述首次检测时的类型。
- 每通道每段最多首次报警一次，避免事件洪水；后续完整累计看任务摘要。
- 队列满沿用 events_dropped 机制，不阻塞。POWER_OFF 关闭事件接纳后不重新打开队列，
  最终统计仍保留到摘要。

记录 v01、DTF2/DTA1、A-B 心跳布局不变。两个接收器新增名称映射；独立地面站显示
“光谱接收数据丢失”。旧接收器仍可接纳未知事件码及 error 严重度。

## 验证范围及待做实机测试

主机 C 回归覆盖未启动、增量累计、重复采样、首次异常、最终快照、关闭后忽略、清理重试、
新段重启和 32 位计数回绕。编译测试要求 1000 Hz 通过、100/500 Hz 失败。地面测试覆盖
事件 15 的名称、严重度、参数及中文显示。

DTU 原生 C 测试增加模拟时钟断言：完全无应答约 2.9–3.0 秒结束；可应答但离线使用
20 秒网络预算加有界 EXIT 清理，测试上限 20.8 秒。这不是实机最坏调度时延验证。

实机步骤待操作者配合，不永久改写已验证的 modem 设置：

1. 烧录新构建，正常连接做 60 秒任务，检查零 RX 损失及正常关闭。
2. 断电后隔离 DTU 电源/信号以防 UART 反向供电，其余外设正常，再启动。
   核对无应答探测及时结束，其他初始化通过后仍可建链、SD 采集，心跳 error 5。
3. 恢复 DTU，以安全可恢复方式制造网络不可用，不带电拔 SIM 或拆天线发射。
   核对 profile 通过、网络等待有界结束后仍可建链和记录。
4. 恢复网络和连接，重启检查 profile/network/ground_ack 恢复。
5. 测量完整上电到 READY；实际 A 板验证未就绪时的 1 Hz 重试；SD 卸载后 PC 读回摘要。

COM8/COM9 留给人工监听，不打开；故障注入不得在正式飞行中进行。
